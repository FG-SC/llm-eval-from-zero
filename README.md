# LLM evaluation from zero

**Can we actually tell if an LLM is good?** This repository is a small, real experiment that tries to answer that
question, step by step, for people who are new to evaluating AI models.

One model (`openai/gpt-oss-20b`, an open model from OpenAI, called through [Groq](https://groq.com)'s API) takes a
math test: 100 grade-school word problems picked at random from [GSM8K](https://huggingface.co/datasets/openai/gsm8k),
a public benchmark. Then we ask simple questions about the result and answer each one with an experiment. Every
answer the model gave, every grade and every number is saved here, so you can check all of it.

## What the notebook covers

The notebook is split into six short lessons ("days"), each one a question answered with an experiment:

| Day | Question | What the experiment showed |
|---|---|---|
| 0 | Can we actually tell if an LLM is good? | The plan: one model, one public test, real runs |
| 1 | I gave an LLM a test. What does its score actually mean? | A test is a sample of tasks, not a universal truth about a model |
| 2 | Should I be impressed by the score? | A score from 100 questions is an estimate; the 95% range shows which true scores fit the result |
| 3 | The model was right. The evaluator said it was wrong. | The grading rule, wrong answer keys and badly written questions move the same answers' score from 90% to 96.8% |
| 4 | Would you trust an AI that admits it doesn't know? | Without permission, the model answered almost every unanswerable question with a number; with permission, most of the time it said "unanswerable" |
| 5 | My model improved. Or did it? | Beating the noise of repeating the test is not enough: one irrelevant sentence cost 6 points, but its paired 95% range (-13 to +1) includes zero, so 100 questions cannot tell |

## Key ideas in plain words

- **Benchmark**: a standardized exam for AI models: fixed questions, an answer key, a grading rule and a score.
- **Accuracy**: the share of questions graded right.
- **95% range (confidence interval)**: the true scores that are consistent with what we observed, given how many
  questions we asked. With only 100 questions the range is wide; more questions make it narrower.
- **Grading rule**: how an answer becomes right or wrong. Here the grader compares the final number with the key
  *as text*, so "8.00" is not "8". Rules and keys can be wrong too (Day 3).
- **Abstention**: the model says a question cannot be answered instead of making something up (Day 4).
- **LLM judge**: another language model used as a grader. Useful as a second opinion, not as the truth.
- **Noise**: how much a score moves when nothing changed. A difference smaller than the noise means nothing yet,
  and a bigger one is not automatically real (Day 5).

The notebook explains each idea on the day it first appears.

## What this is not

- **Not a leaderboard number.** The prompt has no worked examples, the model's reasoning effort is low and the
  test is a random sample of 100 questions, so these scores compare with each other, not with published results.
- **Not a verdict on gpt-oss-20b.** One provider, one prompt, one setting, one week. Answers use temperature 0
  for repeatability, while gpt-oss's own guide recommends 1.0.
- **Not a clean test of math skill.** GSM8K has been public since 2021, so the model may have seen these questions
  during training. This experiment cannot test that.
- **Not checked by people everywhere.** The reading of the answers marked wrong (Day 3) was done by AI readers
  and cross-checked with [GSM8K-Platinum](https://huggingface.co/datasets/madrylab/gsm8k-platinum); the AI judge on
  Day 4 was not checked against human labels.

## Run it yourself

You need Python 3.12. Reading and re-running the notebook needs **no API key**; only calling the model again does.

**1. Get the code and install the packages in a virtual environment** (a private folder of packages for this
project, so nothing on your machine breaks):

macOS / Linux:

```bash
git clone https://github.com/FG-SC/llm-eval-from-zero.git
cd llm-eval-from-zero
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Windows (PowerShell):

```powershell
git clone https://github.com/FG-SC/llm-eval-from-zero.git
cd llm-eval-from-zero
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**2. Open the notebook with that environment.** This is the step that usually goes wrong: the notebook must run on
the `.venv` you just created, not on another Python.

- **VS Code:** open the folder, open `notebooks/llm_eval_from_zero.ipynb`, click **Select Kernel** (top right) →
  *Python Environments* → `.venv`.
- **Jupyter:** `.venv/bin/python -m jupyter lab` (Windows: `.venv\Scripts\python.exe -m jupyter lab`).

**3. Run all cells.** If the first cell stops, its message says which packages are missing and for which Python; it
almost always means step 2 picked the wrong kernel.

Windows tip: clone into a short folder (for example `C:\code\llm-eval-from-zero`). Some dataset files have very long
names, and Windows refuses paths longer than 260 characters unless long paths are enabled. The notebook itself
never downloads anything; only the tests and new runs download the datasets (internet needed the first time).

1. Copy `.env.example` to `.env` and put your key in it (`GROQ_API_KEY=...`). Never commit `.env`.

```bash
python -m src.run --list            # every run defined in configs/runs.yaml

python -m src.judge --run r3_c2_p0 --run r3_c2_p1 --name judge_r3   # Day 4's second check (AI judge)
python -m src.analyze               # results/*/  ->  results/summary.json
python -m src.tables                # refresh the results table above from summary.json
```

`src.run` is a thin wrapper around EleutherAI's
[lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness): it sends the same requests as the plain
harness command below, and adds request pacing, a log of every request with its token count, a quota guard and a
local answer cache (so re-running costs nothing on the same machine; on a fresh clone, run
`python -m src.response_cache --rebuild` first to refill it from the saved request logs).

```bash
OPENAI_API_KEY=<your Groq key> python -m lm_eval run --model local-chat-completions \
  --model_args model=openai/gpt-oss-20b,base_url=https://api.groq.com/openai/v1/chat/completions,num_concurrent=1,max_retries=10,seed=2026 \
  --include_path tasks --tasks gsm8k_seed100 --apply_chat_template \
  --gen_kwargs reasoning_effort=low --log_samples --output_path results/plain_cli
```

The notebook is written as a plain Python file, `notebooks/llm_eval_from_zero.py` (jupytext format), and the
`.ipynb` is generated from it:

```bash
python -m jupytext --to ipynb --set-kernel python3 notebooks/llm_eval_from_zero.py
python -m nbconvert --to notebook --execute --inplace notebooks/llm_eval_from_zero.ipynb
```

Tests: `python -m pytest`.

## How the repository is organized

```
notebooks/   the notebook: start here
results/     everything the model answered, how it was graded, and summary.json with every number
data/        which 100 questions were drawn (IDs and fingerprints), the review of the answers marked wrong, the
             GSM8K-Platinum check
tasks/       the exam definitions for lm-evaluation-harness (questions, prompts, grading rules)
configs/     the model, the AI judge and the list of runs
src/         the code: running exams, statistics, analysis, and the notebook's tables and charts
tests/       automated checks (numbers, grading rules, the notebook's claims)
```
